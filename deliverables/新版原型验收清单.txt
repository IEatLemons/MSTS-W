版本：excel-ledger-v1

[1] 旧版封版
旧版 33 项测试、构建及离线检查通过后封存。
标签 archive/full-finance-20261020；源码及离线包见 releases/full-finance-20261020。
打包脚本核对旧版入口 SHA-256，确保重构不改写封存版本。

[2] 14 个分表
SOFP → Cost Checking → Bank Verification → Shipmanagement RCVD → Expenses Lists → CTM Expenses List → Shipmanagement Cost → Owner Cost → Take-Over Cost → BMA Flag Change → DD Cost → 分析 → Account Code-2版 → 伙食海关库房管理。
已逐一检查导航及页面标题，无额外业务模块。

[3] 角色与两次确认
服务层限制仅财务可写入；只读身份禁用操作。
首次预览不写入；二次确认保存；重复提交、修改后重预览、预览后切换角色均有保护。

[4] 未付款与分次付款
费用 1,000 先登记不改银行；付 400 后待付 600，再付 600 结清。
20 手续费随首次支付计算一次；银行合计支出 1,020。

[5] 分类、修改与作废
3,000 分为船管 1,000、接船 2,000，总表一笔。
修改分类、金额后同步更新；作废保留原因和前后记录并同步剔除影响。

[6] 备用金、编码、估算和月度资料
补给 1,000 不增加费用；现金消费 100 只确认一次。
分次现金付款按比例归集；编码同组唯一；估算按除法；库存保留原表符号规则。

[7] 保存、附件及隔离
刷新恢复新版记录，数据库 msts-excel-ledger-demo-v1 与旧版隔离。
本地附件可保存与读取；无 IndexedDB 时明确提示会话模式。
原始银行 92,779.85、备用金 29,908 和差额 -2,790.58199837597 保持原值。

[8] 验证命令
npm test：31 项业务、船舶隔离与存储回归测试。
npm run build：生成 Vue 构建和自包含离线入口。
npm run check:offline：核对 14 分表、离线资产、封存入口及原 Excel 哈希。
浏览器检查包括录入、收付款、修改、作废、角色限制、刷新恢复及导航。

离线运行验证边界：内置浏览器禁止 file:// 协议，已通过离线包静态完整性检查；直接双击 HTML 的浏览器运行效果仍待人工确认。

[9] 全局船舶范围验收
支持全部、单选、多选、船名/IMO/公司搜索、禁止空选及刷新保留。
A船费用1000、B船2000，多选汇总3000；A船支付400及手续费20后，B船资金仍为0。
两船SOFP导出核对：只含A/B船，费用3000、待付2600。
同月A船伙食收入由100修改为150后，B船仍为200。
只读身份可以筛选及导出，不能新增船舶和账目。
14个分表均已检查标题和切换，原船独立查看余额及未平差额不变。
v1升级测试保留旧编号、附件标识和操作记录，其他船名估算建立独立待完善档案。
浏览器测试使用独立5186端口的空账本；原5173端口的演示记录不受测试数据影响。
