MSTS · Excel 分表记账原型操作说明
版本：excel-ledger-v1

1. 打开项目
在项目根目录执行 npm run dev，浏览器访问 http://127.0.0.1:5173。
首次使用先执行 npm --prefix prototype ci 安装依赖。
也可直接用浏览器打开根目录 index.html；此文件包含页面、代码、样式和 Excel 示例，无需网络。
执行 npm run build 会同步生成根目录及 prototype/dist 的离线入口。

2. 页面结构
侧边栏严格保留原工作簿 14 个分表及顺序，英文原名下附中文释义。
默认打开 SOFP。费用总表及分类表共用同一笔新账，编号一致。
SOFP、Cost Checking 可点击分类下钻。收支表可搜索、按日期或状态筛选，并导出当前表 CSV。
原表列较多时可横向滚动，表头和前两列固定。
SOFP、Cost Checking、分析及月度库存页可展开“Excel 原始底稿完整内容”查看原值及公式异常。

3. 财务身份与两次确认
顶部选择“财务”或“只读查看”，默认财务。
仅财务可新增、修改、作废、登记收付款及维护辅助资料。只读身份可查询和导出。
点击“记一笔账”后：
  ① 先选入账或出账，再选择记账用途。
  ② 填写原表业务字段、金额、分类分配及附件。
  ③ 点击“确认并预览”：只生成完整信息，不保存、不改变资金。
  ④ 核对明细、计算结果、资金影响及将出现的分表。
  ⑤ 点击“确认录入”才实际保存。返回修改后需要重新生成预览。
同一份预览只允许提交一次；预览后切换为只读不能确认保存。

4. 费用、付款与分类
费用未付款时直接登记，关闭“已实际收付款”，银行余额保持不变。
在新账详情中点“登记付款”，填写账户、实际日期、金额、手续费和回单，预览后保存。
例如费用 1,000 USD：先付 400、手续费 20，待付为 600；再付 600 后结清。
两次银行支出合计 1,020 USD。审批附件或原表状态本身不会扣银行。
Bank Verification 可选择已有未结清账目，再关联登记，避免重复新增费用。
一笔费用可拆分多类，分配合计必须等于费用金额。总清单保留一笔，各分类仅展示分配部分。
费用原币按原表“原币金额 × Rating”计算 USD；发票 USD 可保留与 PO 不同的实际金额。
实际收付款、分类分配和手续费均按 USD 填写。Profit、C/N 和船东字段保留原表独立输入口径。

5. 收款和备用金
收款可先登记计划，只有实际到账部分进入资金及五类收款分配。
“银行补给备用金”从银行转入现金，减少银行、增加备用金，不产生费用。
消费请选择费用用途并使用现金账户支付；CTM 和月度页面引用同一笔消费。
填写 CTM 的伙食、招待品分项后，月度页按实际现金付款比例归集。
直接银行收支和结息必须填写完整的实际信息。

6. 附件、修改和作废
支持付款批准、发票、Credit Note、BankSlip 和补充附件。每个类别均可一次选择多个文件，也可分批继续添加、逐个移除；单个附件最多 10 MB。
附件与账目保存在当前浏览器，记录详情可下载查看。原 Excel 只有附件名称，不包含外部原文件。
本次新账可修改或作废；每次先预览影响，再确认保存。
已付款账目不能改成另一种方向或用途，修改金额不能低于已付金额。
作废保留原账、原因和时间，相关分类及资金计算同步剔除该笔演示账目。
“操作记录”可查看修改前后的完整内容。

7. 三个辅助分表
“分析”：维护估算项目，沿用原表“原币金额 ÷ Rating”的除法规则，不产生资金。
“Account Code-2版”：分船管编码和船员细项，维护编码说明及责任部门；同组编码不能重复。
“伙食海关库房管理”：选择月份，维护备用金期初、伙食及招待品收支和库存。
辅助资料均须预览并确认后保存。
伙食支出沿用原表“采购＋上期库存－本期库存”；Bound Store 按原 U27 加总，库存按填写符号参与。
月度输入不生成银行流水；同一笔已关联现金支出请勿再次填入手工采购项。

8. 本地恢复与原始底稿
刷新后会恢复同一浏览器、同一访问地址下保存的账目与资料。
开发服务与 file 离线地址可能属于不同存储空间；更换浏览器、地址或文件位置不会自动同步数据。
存储不可用或保存失败时，顶部明确提示“仅当前会话有效”。
“恢复 Demo 底稿”清除本版演示录入及附件，恢复原始示例；不会清除旧版数据库或修改 Excel。
原始基线：银行 92,779.85 USD，备用金 29,908 USD，未平差额约 -2,790.58 USD。
差额、空白、原始精度及 #VALUE! 均保留，不自动调平或将缺失信息认作零。
Excel 示例行只读；“以此新增”创建独立演示账目，不会改写原行或按相似摘要自动合并。

9. 旧版与边界
旧版入口：releases/full-finance-20261020/index.html。
旧版源码包及预算文档保存在同目录；Git 标签为 archive/full-finance-20261020。
本版不建设总账凭证、财务审批、期间结账、资产折旧和税务系统。
角色、账户和操作均为本地演示，未连接真实支付、生产权限或服务端。

10. 全局船舶选择与按船记账
顶部“查看船舶”可按船名、IMO 或所属公司搜索，勾选一条或多条后点击“应用筛选”。
首次默认“全部船舶”，以后新增船舶也自动包含在全部范围中；切页和刷新保留上次选择。
“恢复全部”一键清除船舶范围限制；清空选择后不能应用。
SOFP、Cost Checking、费用、收款、银行、备用金、分析、月度库存、待收付款、操作记录和导出均遵循所选范围。
费用编码是公共字典，各船共用。原 Excel 底稿仅在所选范围包含原船时显示。

财务点击“管理船舶”可新增或编辑船名、IMO、所属公司，仍须预览并再次确认。
船名必填，IMO 和公司可留空；船舶改名不改变账目归属。
新船不继承原船的账号和历史。没有历史的船显示本次登记净额，不能据此当作完整实际余额。
本次不提供历史导入操作，数据结构已按船预留独立历史基线和来源明细的位置。

记账仍先选入账或出账，随后填写必填的“所属船舶”。
明确单选一船时自动带入；选择全部或多船时需要选择本笔账的船舶。
预览、详情、付款及附件均跟随该笔账的船舶。已有账目不能直接改属另一船，误选请作废后重新录入。
各船银行流水各算各的逐笔余额，多船查看不将不同账户接成一条余额链。
同月可分别维护各船月度资料；多船视图显示各船明细和 USD 合计，人民币折算在单船视图中按各船参数展示。

本地数据从版本1自动升级为版本2，数据库名称不变，原编号、附件文件和审计记录保留。
旧估算已填其他船名的会建立待完善船舶档案，请在“管理船舶”中补充。
“恢复 Demo 底稿”会同时清除本版新增船舶，恢复原 Excel 对应的一条船；请先确认不再需要当前演示数据。
